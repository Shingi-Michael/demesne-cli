# Desktop app

[Documentation index](README.md) · [Implementation](../apps/desktop/README.md) · [Configuration](configuration.md) · [Security](../SECURITY.md)

Demesne uses Electron and bundled Chromium on macOS, Linux and Windows. Its HTML/CSS/TypeScript interface covers conversations, diffs, checks, authentication, subagents and Drive. The Bun daemon owns coding turns and session data.

## Prerequisites

For development, install [Bun 1.4.0](https://bun.sh) and Node.js 22 or newer for packaging tools. No Rust or system webview development libraries are needed. Build on the target operating system and architecture so the compiled Bun backends and native image codecs match the package.

On macOS, install Xcode command-line tools for packaging. Linux needs a graphical session and Chromium runtime libraries (GTK 3, NSS, ALSA, GBM). Windows packaging uses NSIS. Native window capture remains macOS-only; Windows end-to-end behavior is not yet verified.

## Run from source

```sh
bun install --frozen-lockfile
bun run desktop
```

Use **Open project** to select a folder. Your sessions and private `desktop-ui.json` preferences remain in the same daemon data directory.

## Build an app

```sh
bun run build:desktop
```

Outputs under `apps/desktop/release` are a macOS `.app`, Linux `.deb`, or Windows NSIS `.exe`. Use `bun run build:desktop -- --dir` for an unpacked package. The package includes Chromium, the Bun host and daemon, frontend assets and native image dependencies. End users do not need Bun, Node.js or Rust. Configured external tools and model servers remain separate dependencies.

The release workflow (run on a version tag) produces platform artifacts and checksums, including `demesne-desktop-linux-x64.tar.gz`, the unpacked Linux app with its icon that `install.sh` installs per user. `install.sh --source` builds this package from a clone instead. Release signing, notarization and automatic updates still need configuration. Keep the complete application together; copying a single executable loses required resources.

The [release workflow's public-distribution TODO](../.github/workflows/release.yml) remains an unresolved macOS release blocker, not a stale note: `electron-builder.json` explicitly sets `mac.identity` to `null`, and the workflow neither imports a Developer ID certificate nor signs, notarizes or staples the macOS artifacts. It also does not execute the x86_64 CLI artifact (`smoke: false`). Before public distribution, configure signing and notarization credentials, publish archives containing the stapled app, and add an Intel or Rosetta smoke test. The current tag-triggered release job does not enforce these prerequisites.

## Closing the app and stopping work

On macOS the window's close button hides it; click the Dock icon to return. Quit exits the app and its UI host. On Linux and Windows, closing the window quits. Daemon-owned turns continue after app exit. A running Drive mission is handed to a detached Bun host; reopening the project reclaims it. Use Esc twice or the stop square to cancel a turn, and Pause or Stop on a Drive mission's turn. Stopping the daemon is a separate operation.

The last project and session are restored on launch. Missing or archived sessions open a new session instead. Avoid opening two clients that orchestrate the same Drive mission.

## Verification

See the [implementation guide](../apps/desktop/README.md#verification). Electron lifecycle checks exercise the real Chromium renderer with a disposable workspace and deterministic model, including approvals, edits, persisted sessions and background work. No personal credentials or production test endpoint are used. Tests currently run on macOS and Linux; Windows packaging and backend checks do not establish full UI compatibility. Virtual displays do not establish performance on every physical GPU.

## Foundry in a conversation

Ask for a mockup, interactive page, graphic or document in any chat, or use `/foundry` followed by what you want to make. This works in a project and in **Just a chat**. The model saves the artifact and its preview appears directly below the reply; the Foundry sidebar page keeps the same work in a gallery.

HTML mockups run inside the conversation with working buttons and inputs. Preview state survives streaming replies, completion, opening the step trace and later messages. **Code** shows the source, **Phone** narrows the viewport, and **Revise** prepares a follow-up naming the artifact. Ask for a change to save another version in the same chat. SVG graphics and Markdown documents also appear inline.

Revisions work like edits to a file: the model reads the artifact, then changes just the parts you asked about with `foundry_edit` (exact find and replace, each match required to be unique) and only rewrites the whole source when most of it changes. Every change names the version it was read from, so if the artifact moved on in the meantime (you used **Edit source**, or another chat saved) the change is refused and the model reads the latest version first instead of overwriting it.

Previews run in sandboxed frames. A page may load pinned libraries from cdnjs, jsdelivr and unpkg (an exact version such as `react@18.3.1`) and Google Fonts; every other request is blocked, so images are inline SVG or data URIs and nothing can phone home. The tools carry a short design brief (colours as custom properties with a dark-mode set, hairlines and tones instead of outlines, works at phone width, no stock AI looks, Demesne's own tokens when you ask for Demesne's UI) so artifacts read as one hand.

After building the app, run `bun scripts/check-foundry-chat.ts` to verify in-chat creation, interaction, revisions and history replay in real Electron. Pass a packaged executable as the first argument to check an installed build.

## Compacted conversation

After successful compaction, the conversation shows the saved summary in place of older turns. The retained recent turns and subsequent messages stay visible. Use **Expand full history** on the summary card to restore the complete chronological conversation, then **Collapse older conversation** to return to the summary. Expansion stays in effect during streaming updates; reopening a session or creating a new checkpoint starts collapsed. This changes only the view; the complete transcript remains saved. Failed or cancelled compaction does not create a new collapsed section.

## Workspace layout

The left sidebar starts with **New chat** (⌘N) and **Search** (⌘K): Search is a row like New chat until you type into it, and the list narrows to matching chats and projects as you type; Escape clears it. Below them come **Pinned** chats, then one group per project, then **Just a chat** for chats with no folder. Each group heading is a row at chat size: a project shows its folder, shut or open with it, and Pinned, Just a chat and the date and status groups show their own mark. Click the whole row to fold or unfold that group on its own; a group's chats hang from its heading on a thin guide, and the folds survive reopening the app. The project you are in starts open, other projects start folded, and switching to a project opens it. Drag a project name above or below another project to set your own order; the insertion line shows where it will land, and with a project name focused, Alt+↑ and Alt+↓ move it one position. Pointing at a project's line shows **+**, which starts a new chat in that project (switching to it), and Group and sort. Click a chat to switch directly to that conversation. Each project's line ends in its state: a green branch count when Drive's branches wait for review, an amber ring when a chat needs you, a breathing dot while one works when it is folded, the branch you are on for the open project, or how many chats a folded one holds. Other agents working in a project (over Heartbeat) show as small marks on its line; see [Heartbeat](heartbeat.md#agents-nearby). Branches to review show as a green **Review N branches** row at the end of the open project. Each group shows six chats; **Show more** reveals the rest. ⌘O, or **Open a folder** under the composer, opens another folder.

Pointing at a group heading trades its count for **Group and sort** (⇅), which unfolds under the heading at reading size: group by **Project**, **Date** (Today, Yesterday, This week, This month, Earlier) or **Status** (Needs you, Working, Failed, New replies, Done), sort by **Recent** or **Name**, and **Archived chats** with how many there are. By date or status, each row names its project on the right. **Archived chats** opens **All chats** in place of the conversation, with an Active and an Archived tab; **Restore** on an archived chat puts it back in the list. Escape leaves the page.

Pointing at a chat shows **Pin** and **Archive** at the end of its row. A pinned chat moves to **Pinned** at the top, whichever project it is in, and the daemon keeps the pin. Archive takes the chat off the list at once; ⌘Z brings it back within a few seconds, and after that it is under **Archived**. Double-click a title to rename it. Arrow keys, Home and End move among visible chats; Delete or Backspace archives the focused one. Ctrl+Tab and Ctrl+Shift+Tab step through the visible chats. Chat marks show waiting for approval or an answer, work in progress, a new reply, or failure; a pinned chat with nothing to show carries a pin. Drive worktree chats stay under their parent project with a branch mark.

**Scheduled**, under Search, opens a page in place of the conversation for chats that start on their own. A routine is one sentence, when and then what: "Every weekday at 8:30, summarize what Drive finished overnight", "Fridays at 5, tidy merged branches", "Every morning, read the failing checks". Write it in the box at the bottom and press Enter; if it can't tell when, it says how to write one. At its time the daemon opens a chat in the project you wrote it in (or a plain chat, from a plain chat), with the what as the first message, whether or not a window is open. A project's routine runs on Auto, like a Drive mission, since nobody is there to approve. A slot missed while the computer slept still runs when it wakes, within 12 hours. Each routine shows when it runs next and has **On**/**Off** and **Delete** on its row. Drive's own runs after 20 quiet minutes sit in the same list with their switch, and **Last runs** opens this week's routine chats.

**Customize**, under Scheduled, gathers what shapes how Demesne works in the project: its instructions file (`DEMESNE.md`, or `AGENTS.md`), its commands (`.demesne/commands`) and workflows (`.demesne/workflows`), yours from `~/.demesne` marked *yours, every project*, and the connectors with their state. **Edit** unfolds a file under its row; ⌘↵ or **Save** writes it where it lives, and the next turn reads it. **Write it** starts an instructions file when there is none. Type a name in the line under Commands or Workflows and press Enter to start a new one from a short template. **Run** puts the command in the composer. In a plain chat the page shows only your own files. Customize edits nothing else: only those Markdown files, never through a symlink.

The sidebar's foot names you and what pays for the models (your Codex plan, ChatGPT credits, or the provider), with a sun or moon that swaps between your last light and dark themes, and **Settings** (⌘,).

The toolbar toggle folds the sidebar into a 60px rail (the mark, **+**, conversations with an amber ring when one needs you, a branch icon when Drive has a branch to review, Drive's progress ring and Settings) and remembers the preference. The Dock icon counts the chats that need you, so it shows from any app. Native system notifications on Linux, macOS and Windows say when a chat waits on your approval or answer, finishes, stops with an error, or Drive has a branch ready to review. They appear only while the app is out of focus; clicking one restores the window and opens that chat. **Settings › Notifications** has a switch for each kind, all on by default; saved choices are preserved. The app must remain running (minimized or hidden is fine), and your OS must allow notifications for Demesne. Linux also needs a desktop notification service; Windows toasts use the installed app's identity. The top bar shows the conversation's title, its branch, and **⋯**. When the branch has changes since the last commit, its chip shows the lines added and removed, and clicking it asks for a commit, a push and a pull request as the next turn. **⋯** is a small menu for this conversation (rename, compact with the context used, new chat, settings). There are no side panels, and Drive has no page: it lives on a line at the end of the conversation (below), and a turn's edits, commands and checks unfold in place under their steps, and `/diff` unfolds the latest turn's edits.

A new chat opens with a greeting ("Thursday evening · project on branch", then "What are we building, Mike?", the name from git's `user.name`), one short paragraph of what happened while you were away, and the composer. The paragraph is written from the app's own state, at most three sentences, what needs you first: a chat waiting on your yes (and to do what), Drive's finished branches and which failed a check, what Drive or another chat is working on now, a routine that ran, then Drive's ideas and how often it asked you this week. "Since you left" counts from the last time the window was in front of you. Each underlined phrase opens its thing right under the paragraph: a waiting chat's phrase unfolds its approval (**Allow**, **Always**, **Deny**, or **Open chat ›**) so you can answer it without leaving Home, Drive's branches unfold as rows with Apply, PR and Discard, and its ideas unfold with Run, Plan and Not now. The underline's colour says the kind: amber waits on you, red failed, blue is going on now. **Pick up** under it goes back to the chat you were last in and quotes the last thing you asked there. Drive's best idea is the composer's ghost text; Tab takes it. A model whose provider gives no name reads in words ("qwen3.8-27b" as "Qwen3.8 27B").

A conversation reads as one column. Your ask is a bubble on the right with its time under it. A turn shows "Thought for 1.2s", then its steps as one quiet line each on a thin guide (an icon, the verb, the target in monospace, and what came of it on the right); an edit's row unfolds its diff in place and a command's row unfolds its output. When a background command serves a page on this machine (it prints an address such as `http://localhost:5173/`), its row reads **Serving** with the address, and the live page unfolds under it: **Desktop** or **Phone** width, **Reload**, **Output** to see the command's log instead, and **Open ↗** for your browser. The preview loads only localhost addresses, and the page can't open windows or navigate the app. The answer sits beside a small **d.** mark, and the receipt under it says the model, the time, the speed, how many files changed, whether the checks passed and how many steps there were, with **Copy** and **Undo changes**. Click **N files changed** in the receipt to unfold every file the turn changed under the answer. Click any line to leave a note under it (Enter keeps it, Esc drops it); the composer shows how many notes are waiting, and your next message sends them first, one line per note, followed by anything you typed. A message can be only notes. A permission is one amber row above the composer: **Allow ↵**, **Always** and **Deny Esc**, with **command** or **diff** to unfold the whole thing; typing in the composer says what to do instead. Nothing sits on the composer. What Drive is doing shows as a quiet line where the conversation ends ("Drive has 3 ideas for what's next", or "Drive is working" with a hairline that fills as it goes); click it and the line becomes Drive's reply, its ideas or the running mission unfolding under it and scrolling with everything else, so nothing is covered (Esc or the line's chevron folds it away).

Settings (⌘,) is a page in place of the conversation, and the sidebar becomes its list while it is open: **Back to chats**, a search, then thirteen sections in four groups. *You*: **General** (open on Home or the last chat; keep the Mac awake while a turn or Drive runs), **Notifications** (a switch per kind of banner), **Appearance** (the theme as a word that unfolds every theme in place, with Undo after a change; **Make a theme**; text size), **Keyboard shortcuts**, **Archived chats** (with Restore) and **Usage** (the last 30 days by model: turns, how many finished, speed; and Drive's runs). *How it works*: **Permissions** (this chat's mode; every rule it learned from Always, each with **Ask again**; the folders you trust, each with **Untrust**; how often it asked this week), **Drive** (this project's switch for starting on its own, and a mission's limits on time, tokens and tasks, typed as numbers like 400k), **Models** (the chat's model, the model subagents run on, the image model, and a turn's limits on model rounds and tool calls) and **Providers**. *Around it*: **Connectors** (each MCP server with its state and tool count; add one by name and command, or remove one you added) and **Heartbeat** (on or off, and the agents nearby). *This computer*: **Data and daemon** (where data and settings live, the daemon's address, Restart the daemon, all conversations and cleanup). Each row is a title, one quiet line and its control: a switch, segments, a word that unfolds its choices under the row, a typed number (Enter or leaving the field saves it), or a link. Changes go to `~/.demesne/config.toml`; the ones the daemon reads only when it starts say so until you restart it, which waits until nothing is working. Typing in the search looks through every section and marks the words; Esc clears it, and Esc again (or Back to chats) closes Settings. ↑↓ step through the sections while no field has the keyboard.

On a window at least 1100px wide, a column of cards sits to the right of the conversation; the panel icon in the top bar shows or hides it (remembered). **Environment** names where the chat works (this computer, the folder, the branch) and whether Heartbeat is on. **Context** splits what the context holds (chat, tools, kept free) with **Compact now**. **Changes** lists the files changed since the last commit with **Commit & PR**. **Agents** (other Heartbeat agents in this project, Message on hover), **Drive** (its ideas, Run on hover), **Preview** (what a running command serves, Open ↗) and **Connectors** (MCP servers and their tool counts) appear only when they have something. Clicking a card's header folds it to one line with its summary. While the cards show, the composer's context ring and the top bar's branch chip stand aside, since the cards carry both.

The composer is one box for what you type, with a faint ↵ in its right corner that brightens once there is something to send and becomes a stop square while a turn runs. Under the box, as plain words, sit **+** to attach images, the chat's mode, and on the right the model with its thinking level and a context ring. Thinking starts off: a model that can turn it off runs with it off, and one that can't (such as GPT-6.1 Sol) runs at its lowest level, until you pick a level in the model picker. Click the model word to open the picker: one panel with a search on top that looks through every provider at once, your four most used models numbered 1–4 (the numbers pick while the search is empty), then **Thinking** for the model you point at or arrow to, as a track with one stop per level and the level's full name (Extra high, not xhigh); a model without thinking says None. ←→ change the level and clicking a stop switches to that model at that level. **More models** unfolds the rest in the same panel by provider, with large catalogs such as OpenRouter's behind **Search all N**. The mode is one word: **Ask** (every edit and command asks first), **Accept edits** in green (file edits, new files and moves run without asking; deletes and commands still ask), **Plan** in blue (reads and proposes, changes nothing; the box's edge turns blue too) or **Auto** in amber (everything runs without asking). Click the word or press ⇧⇥ in the composer to step to the next one; the word opens into all four modes in place, the current one lit, and folds back a moment later, so nothing appears above the box. Each chat keeps its own mode, and a new chat starts in Ask. Images (PNG, JPEG or WebP, up to six per message) attach by **+**, by pasting into the composer, or by dropping them anywhere on the window. They sit as small thumbnails inside the box above your text; hover one for × to remove it. Sent images show above your message, and the model receives them with it: as pixels when the provider takes images (Codex, ChatGPT, or `provider.vision = true`), otherwise as their names and sizes. Mention files with `@`. Clicking the ring unfolds its breakdown above it (conversation, tools, what is kept free for replies, and free space, with **Compact now**); Esc or a click away folds it. Surfaces are tones over the background with hairlines where an edge is needed, not outlines: three corner radii (6, 10, 14) and one shadow ramp, and anything that appears, folds or moves eases in over 140–220ms (none of it under `prefers-reduced-motion`). Inter and JetBrains Mono ship with the app. Conversations use Inter for reading and retain monospace for code and diffs. Settings, provider setup, model selection and approvals share the same spacing and theme roles; existing dark, light and custom themes remain available.
